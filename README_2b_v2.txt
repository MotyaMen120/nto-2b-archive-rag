Отдельное решение: solution_2b_v2.py

Полный запуск и архив после завершения:

  py -3.12 -X utf8 prepare_weights_2b.py
  py -3.12 -X utf8 run_complete_2b.py

Первый скрипт заранее скачивает закреплённые веса E5-large и BGE-reranker,
проверяя SHA256. Второй работает офлайн: 800 OOF -> обучение -> 400 test ->
официальная валидация -> solution_2b_complete.zip. Итоговые измерения и S
записываются в output_2b_final/completion.json после окончания полного прогона.
Reader Qwen2.5-7B тоже должен быть заранее доступен локально или в HF-кэше.
Предобученные веса в архив не включаются; их источники закреплены в manifest.

Запуск из папки проекта (Python 3.12):

  py -3.12 -X utf8 solution_2b_v2.py --mode smoke
  py -3.12 -X utf8 solution_2b_v2.py --mode audit --output output_2b_v2/data_audit.csv
  py -3.12 -X utf8 solution_2b_v2.py --mode retrieve --lexical-only --output output_2b_v2/retrieval.csv

Последняя команда пишет retrieval.report.json, без CSV предсказаний. Это диагностика
фиксированного поиска по train, без обучения и без оценки качества ответов.
Recall@K — средняя доля всех золотых постов в топ-K; hit@K — доля вопросов,
где найден хотя бы один золотой пост. Вопросы no_info исключены из этих средних.
При наличии файла групп audit/retrieve/val проверяют GroupKFold и сохраняют
соответствие qid/group/fold в <output>.groups.json. CSV в режиме audit не создаётся.
В режиме retrieve отчёт дополнительно содержит диагностику каждого фолда.

Что реализовано:

* Словарь перифраз, разбиение сравнений на подзапросы, даты, BM25 + dense MaxP + RRF,
  второй проход по терминам опорных постов и добавление концов найденной хронологии.
* Корпус сортируется по date,post_id. До скоринга выбирается префикс <= asked_at.
  BM25 использует df и среднюю длину только этого префикса; dense оценивает только
  допустимые чанки (GPU-префикс или CPU-батчи по 8192). Будущие посты не меняют прошлый поиск.
* Float16 .npy memmap, ключ кэша учитывает содержание корпуса, параметры чанкинга,
  модель и локальные файлы весов. Длинные посты включают последний чанк.
* Необязательный фиксированный cross-encoder с одним логитом релевантности.
  Полноценные E5/BGE и cross-encoder должны быть подготовлены заранее.
* Контекст выбирается с удалением репостов и сортируется по времени. Бюджет
  токенов учитывает системный промпт; скрытого обрезания всего промпта нет.
* Reader получает JSON-контракт. Арифметику выполняет Python Decimal/date без eval.
  Числа и даты операндов проверяются по точным цитатам либо по датам публикаций.
  Ошибочные JSON, неизвестные источники и неподтверждённые вычисления дают skip.
* Verifier по умолчанию проверяет расчёты, исторические вопросы и no_info.
  Переключатели: --verify auto|all|none.
* Evidence: сначала опорные посты каждого шага, затем репосты из других каналов
  в окне +/-2 дня с согласованными числами. no_info имеет пустое evidence;
  skip сохраняет найденные посты. Цитировать можно только видимый контекст.
* Модели энкодера, реранкера и читателя загружаются последовательно и выгружаются
  через удаление объекта, gc.collect(), torch.cuda.empty_cache().
* Режим val требует настоящие train_groups.csv и GroupKFold(5). Группы не
  восстанавливаются по эвристикам. Словарь/энкодер/CE/reader фиксированы и не обучаются
  на разметке; поэтому исходные прогнозы не используют ответы собственного фолда.
* val --calibrate обучает регрессор ожидаемого выигрыша над skip на четырёх фолдах,
  применяет к пятому, затем сохраняет модель, обученную на всём OOF для test.
  Цель вычисляется официальным score.py, с AP@5 и особыми правилами no_info/skip.
  Ручные пороги no_info, promised и skip не подбираются на train.
* --train-meta добавляет LightGBM LambdaRank для финального evidence. Reader
  использует фиксированный CE-контекст, независимый от обучаемых рангов.
  С --calibrate внутри внешних обучающих фолдов выполняется вложенный GroupKFold(5),
  чтобы калибратор получал обучающие evidence без собственной разметки и без
  разметки внешнего проверочного фолда. На test применяйте --meta-ranker вместе
  с соответствующим --calibrator. run_complete_2b.py делает это автоматически.
* Reader генерирует пакетами (--reader-batch, по умолчанию 2) с уменьшением батча
  при CUDA OOM. --resume продолжает совпадающий JSONL checkpoint; параметры,
  код, модели, фолды и входной контекст проверяются. Подписи моделей переносятся
  между папками: они основаны на содержимом файлов.
* Каждый итоговый CSV проверяется API и CLI официального submission (3).py,
  дополнительно проверяются даты, повторы evidence и пустое evidence у no_info.
* Отчёты содержат a/e/S, срезы level x answer_format, Recall/Hit, ошибки и confusion.
  RSS измеряется с дочерними процессами, VRAM — средствами PyTorch.

Данные автоматически определяются по базовым именам и суффиксам скачивания (2),
(3), (5). Приоритет: базовое имя, иначе наибольший номер суффикса.
Можно явно передать --corpus, --train, --test, --groups, --output, --data-dir.

Запуск с моделями, подготовленными до офлайн-инференса:

  py -3.12 -X utf8 solution_2b_v2.py --mode val --encoder "weights_2b/e5-large" --reader "Qwen/Qwen2.5-7B-Instruct" --reranker "weights_2b/bge-reranker-v2-m3" --calibrate --output output_2b_v2/oof.csv

  py -3.12 -X utf8 solution_2b_v2.py --mode test --encoder "weights_2b/e5-large" --reader "Qwen/Qwen2.5-7B-Instruct" --reranker "weights_2b/bge-reranker-v2-m3" --calibrator output_2b_v2/oof.calibrator.joblib --output output_2b_v2/submission.csv

Параметры модели/поиска/промпта в val и test должны совпадать: калибратор
проверяет их подпись вместе с версией исходного кода. Для BGE добавьте
--encoder-kind bge в обе команды (CLS pooling, без E5-префиксов).
Обычные веса Qwen загружаются через bitsandbytes NF4 (--quantization 4bit).
Предквантованные AWQ/GPTQ этим решением не проверены. Для маленькой модели
без квантования предусмотрен --quantization none. По умолчанию веса ищутся
в weights_2b/encoder и weights_2b/reader; принимаются также локально кэшированные
HF ID. Все from_pretrained используют local_files_only=True, а переменные
HF_HUB_OFFLINE=1 и TRANSFORMERS_OFFLINE=1 задаются принудительно.

Результаты проверки на текущем компьютере:

* 21 регрессионный тест проходит, включая независимость от будущих постов,
  разделение групп, цитаты операндов, memmap-кэш и официальный валидатор.
  Дополнительно API энкодера и CE проверены на маленьких случайных моделях,
  созданных локально: py -3.12 -X utf8 tests_2b_v2/run_retrieval_integration.py.
  Это проверка интеграции, а не качества семантического поиска.
* Корпус 142226 постов, train 800, test 400. Файл train_groups (1).csv
  автоматически найден: 800 qid, 382 группы. Состав train совпадает полностью;
  между группами нет общих текстов вопросов и золотых post_id.
  GroupKFold даёт 5 фолдов по 160 вопросов (640 в обучающей части каждого фолда).
  Распределение сохранено в output_2b_v2/data_audit.groups.json.
* BM25-диагностика без обучения: hit@100 = 88.42%, recall@100 = 75.22%.
  На heavy: hit@100 = 84.62%, recall@100 = 64.47%.
  Результаты: output_2b_v2/retrieval.report.json. Эти показатели не достигают
  заявленных в предложении целей для полноценного dense/CE-поиска.
* Qwen2.5-7B из локального HF-кэша проверен на двух синтетических вопросах:
  обещание открытия -> promised, разница дат публикаций -> 2 (вычислено Python).
  Официальный валидатор принял синтетический CSV. Это НЕ соревновательный сабмит.
  Весь запуск занял около 65 секунд; RSS 2.79 GiB, CUDA allocated 5.78 GiB,
  CUDA reserved 6.07 GiB на RTX 3070 Ti Laptop.
  Повтор: py -3.12 -X utf8 tests_2b_v2/run_local_integration.py
  Артефакты: output_2b_v2/synthetic_integration/.

Ограничения и оставшиеся эксперименты:

* Важное расхождение предложения с поставленным scorer: score (2).py явно
  обнуляет AP@5 для skip. Сохранение evidence соблюдает AGENTS.md, но в текущем
  scorer не приносит балл за skip. Калибратор использует фактическую метрику;
  порог 1/6 из документа не переносится в код как универсальное правило.
* Настоящая OOF-метрика ответов и калибратор ещё не получены. Группы подключены
  и проверены; режим val использует train_groups (1).csv без явного --groups.
  Режим val останавливается до загрузки весов, если файл групп отсутствует.
* Полный dense/CE-поиск и итоговый S следует смотреть в completion.json после
  окончания полного прогона. Производительность T4 не измерена; локальные
  измерения на RTX 3070 Ti нельзя выдавать за подтверждённый запуск на T4.
* LoRA, LLM query rewrite и несколько независимых генераций не включены.
  Используются обычные веса 7B, словарный rewrite и verifier.
* Второй поиск не гарантирует нахождения самого раннего упоминания.
  Совпадение цитаты проверяет происхождение операнда, а не его смысловую верность.
  Нужны ошибки по OOF, чтобы оценить выбор дат и исторических состояний.
