## 2. Жёсткие инварианты (нарушение = дисквалификация или слив метрики)
1. **Темпоральный барьер (`post_date <= asked_at`)**:
   - Для вопроса с датой `D = asked_at` посты с `date > D` НЕ СУЩЕСТВУЮТ ни на этапе поиска, ни при реранкинге, ни при кластеризации репостов, ни при генерации ответа.
   - Фильтр `post_date <= D` должен применяться на уровне маски индексов до скоринга.
2. **Валидация строго по `GroupKFold(n_splits=5)` с группами из `train_groups.csv`**:
   - Никакого случайного `KFold` — иначе посты одной истории утекут между train и val.
   - Все пороги (`no_info`, `promised`, `skip`), реранкеры и LoRA-адаптеры обучаются и тюнятся строго OOF.
3. **100% офлайн и бюджет ресурсов (1× NVIDIA T4 16 GB VRAM, 12 GB RAM, ≤ 6 часов на всё)**:
   - Запрещены внешние API, сетевые запросы и догрузка весов в рантайме инференса. Все веса — в локальном кэше/папке `weights_2b/`.
   - **12 GB RAM — главный лимит**: храни эмбеддинги корпуса в `float16` (`np.memmap`), не держи одновременно в памяти эмбеддер, реранкер и LLM. Между стадиями всегда делай `del model; gc.collect(); torch.cuda.empty_cache()`.
4. **Строгий формат сабмита**:
   - Колонки: `qid,answer,evidence`.
   - `answer`: `YYYY-MM-DD`, число с точкой без единиц (допуск ±1%), `done|promised|postponed|cancelled`, `yes|no`, буква `a|b|c|d`, либо `promised|no_info|skip`.
   - `evidence`: до 5 `post_id` через пробел, лучшие первыми, все существуют в корпусе и имеют `date <= asked_at`. Для `no_info` поле `evidence` пустое; для `skip` — **оставляй топ-5 найденных постов**, чтобы не терять `0.3 * AP@5`.
   - После каждой генерации CSV обязательно запускай `submission.py` для валидации формата.

- **Heavy (w=4)** — 24.8% вопросов, но **47.3% итогового веса**. 65% всех heavy-вопросов — это:
  1. Арифметика разницы дат (`сколько дней / полных месяцев / на сколько дней позже`) — **вычислять строго в Python**, не в голове LLM.
  2. Проверка исторического состояния на прошлую дату (`можно ли было <дата>...`, `шла ли стройка...`) — строить хронологический таймлайн событий.
- **Evidence AP@5 (`0.3 * e_q`)** — медиана 3 поста и 3 разных канала на вопрос (до 20 постов). Обязательна кластеризация репостов в окне ±2 дня вокруг опорных постов.

## 4. Скилы в `.agents/skills/`
Подключай релевантный скил перед работой над подсистемой:
- `nto2b-eda-validation` — анализ ошибок, GroupKFold-оценка, разбор срезов по `level × answer_format`.
- `nto2b-temporal-retrieval` — деобфускация топонимов, гибридный поиск (BM25 + dense + RRF), 2-hop поиск для таймлайнов.
- `nto2b-rerank-evidence` — кросс-энкодер / парный реранкер и расширение доказательств по репостам для AP@5.
- `nto2b-llm-reasoning` — промпты, JSON-схемы, Python-калькулятор дат/чисел, обработка `promised`/`no_info`/ложных предпосылок.
- `nto2b-calibration-submission` — калибровка порогов `skip`/`no_info`, профилирование T4/12GB RAM, финальная проверка сабмита.
