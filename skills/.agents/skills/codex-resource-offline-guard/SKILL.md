# Codex Resource & Offline Guard — Контроль T4 / 12 GB RAM / Офлайн

## Когда вызывать
- При добавлении новой модели (эмбеддер, реранкер, LLM), изменении batch size, длины контекста или формата кэша.
- Перед сборкой финального решения для сдачи организаторам.

## Жёсткие бюджеты (перезапуск организаторов)
- **GPU**: 1× NVIDIA T4, **16 GB VRAM** (безопасный потолок в коде: **≤ 14.5 GB**).
- **RAM**: **12 GB** (безопасный потолок процесса: **≤ 9.5 GB**).
- **Время**: индексация 142 226 постов + предсказание 400 вопросов **≤ 6 часов** (целевой бюджет с запасом: **≤ 4.5 часов**).
- **Сеть**: **полностью отключена** при запуске.

## Обязательные архитектурные паттерны
1. **Последовательные стадии с полной очисткой памяти**:
   - Никогда не держи одновременно в RAM/VRAM эмбеддер, реранкер и LLM.
   - Между стадиями всегда вызывай helper:
     ```python
     del model
     gc.collect()
     if torch.cuda.is_available():
         torch.cuda.empty_cache()
     ```
2. **Экономия RAM на корпусе (142 226 постов)**:
   - Эмбеддинги сохраняй строго в `np.float16` на диск и читай через `np.load(..., mmap_mode="r")`.
   - Матричные умножения для поиска делай чанками (по 20–30k документов), без материализации полных `float32` матриц.
   - Не храни 3 копии DataFrame корпуса в памяти.
3. **Офлайн-проверка**:
   - Все вызовы `from_pretrained(...)` должны поддерживать `local_files_only=True` (или путь в `weights_2b/`).
   - Прогоняй проверочный запуск с переменными окружения:
     - PowerShell: `$env:HF_HUB_OFFLINE="1"; $env:TRANSFORMERS_OFFLINE="1"`
     - Bash: `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1`
4. **Профилирование и экстраполяция времени**:
   - Логируй время каждой стадии и пик памяти (`psutil.Process().memory_info().rss` и `torch.cuda.max_memory_allocated()`).
   - По 20–50 вопросам экстраполируй время на 400 вопросов `test` + время полной индексации корпуса с нуля (без кэша!).
