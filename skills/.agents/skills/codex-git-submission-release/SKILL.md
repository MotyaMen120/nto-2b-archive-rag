# Codex Git & Submission Release — Релиз сабмита и чистота Git

## Когда вызывать
- Перед каждым коммитом / пушем в `MotyaMen120/nto-2b-archive-rag`.
- Перед каждой отправкой CSV на лидерборд (лимит: 10 попыток в сутки).
- При подготовке финальной сдачи (CSV до 06.12 23:59 МСК, код + анкета до 07.12 23:59 МСК).

## Протокол проверки сабмита (обязательно перед отправкой)
1. Запусти официальный валидатор `submission.py` / `submission (3).py` на сгенерированном CSV. Любая ошибка = блокер.
2. Выполни sanity-check распределений `test` vs `train` (OOF):
   - Ровно 400 строк, все `qid` совпадают с `sample_submission`, дублей нет.
   - Нет `NaN`, пустых `answer`, лишних кавычек, пробелов, `%` или `руб` в числах.
   - Доля `no_info` (ориентир ~1–4%), `promised` (~6–12%), `skip` (обоснованная по OOF), баланс `yes`/`no` и `a/b/c/d` без перекоса в один класс.
   - Среднее число `evidence` на вопрос ~4.5–5.0 (и ровно 0 для `no_info`, не 0 для `skip`).
   - 0 постов с `post_date > asked_at`.

## Протокол Git и GitHub
1. Перед `git add` всегда проверяй `git status` и размеры новых файлов (`> 20 MB` в git не коммитить!).
2. Формат коммитов:
   - `feat(retrieval): add toponym deobfuscation + 2-hop (OOF S: 62.4 -> 66.1)`
   - `fix(math): compute full_months_diff in Python (OOF heavy: +5.2)`
   - `refactor(pipeline): split solution_2b into modules (OOF unchanged)`
3. Не делай `git push --force` в `main` и не удаляй рабочие бейзлайны без сохранения тега/ветки.
4. Для финальной сдачи подготовь чистый `README.md` с одной командой воспроизведения (обучение + инференс с нуля в офлайне) и короткий список использованных моделей/весов.
