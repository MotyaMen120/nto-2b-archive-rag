# AGENTS.md — Правила работы Codex в репозитории `nto-2b-archive-rag`

Этот файл определяет обязательный протокол работы Codex в проекте НТО ИИ 2026/27 (Кейс 2B «Спроси архив»). Любая задача начинается с соблюдения этих правил.

## 1. Протокол старта (перед любым редактированием кода)
1. Проверь состояние репозитория: `git status`, `git branch`, список файлов в корне и `EXPERIMENTS.md` (если существует).
2. Определи актуальную точку входа (например, `solution_2b.py` vs `solution_2b1.py`) — **никогда не угадывай**, проверь, какой файл свежее и используется для последних запусков.
3. Не меняй код «вслепую»: сначала сформулируй 1 конкретную гипотезу, укажи, какие файлы будут затронуты и как будет измерен результат.

## 2. Неприкосновенные инварианты кейса 2B
1. **Темпоральный барьер (`post_date <= asked_at`)**: посты позже `D = asked_at` не существуют ни в поиске, ни в реранкинге, ни в репост-кластеризации, ни в промпте LLM.
2. **Валидация строго через `GroupKFold(n_splits=5)` по `train_groups.csv`**: никакого случайного сплита, все пороги (`skip`, `no_info`, `promised`) и модели оцениваются строго OOF через официальный `score.py` / `score (2).py`.
3. **100% офлайн и лимиты железа**: 1× NVIDIA T4 (16 GB VRAM), 12 GB RAM, ≤ 6 часов на индексацию корпуса (142 226 постов) + 400 вопросов `test`. Запрещены внешние API и сетевые запросы при инференсе.
4. **Строгий формат сабмита**: каждый сгенерированный CSV обязан проходить проверку `submission.py` / `submission (3).py` без единой ошибки.

## 3. Инженерная дисциплина работы
- **1 гипотеза = 1 атомарное изменение = 1 замер OOF**. Не смешивай рефакторинг, смену модели и правку промпта в одном коммите.
- **Нет замера — нет улучшения**: любое изменение пайплайна считается завершённым только после прогона валидации (или smoke-теста при чистом рефакторинге) и записи строки в `EXPERIMENTS.md`.
- **Откат регрессий**: если OOF-метрика `S` упала или выросла в пределах шума при резком росте времени/RAM — откати изменение или вынеси его за CLI-флаг (по умолчанию выключенный).
- **Чистота Git**: никогда не добавляй в git `*.parquet`, `weights_2b/`, `.cache_2b/`, `.venv/`, большие `.csv` с сабмитами и бинарные чекпоинты.
- **Язык**: комментарии в коде, логи экспериментов и отчёты пользователю пиши на русском языке; технические термины и имена идентификаторов оставляй на английском.

## 4. Скилы управления работой Codex (`.agents/skills/`)
Выбирай нужный скил под текущую задачу:
- `codex-repo-onboarding` — аудит репозитория, карта файлов, проверка `.gitignore` и фиксация бейзлайна.
- `codex-experiment-loop` — строгий цикл ML-экспериментов (гипотеза → код → GroupKFold OOF → запись в `EXPERIMENTS.md` → KEEP/REVERT).
- `codex-safe-refactoring` — безопасный рефакторинг скриптов без поломки рабочего бейзлайна и с проверкой эквивалентности.
- `codex-error-debugger` — разбор падений, утечек и топ-ошибок по весу `w_q * (1 - s_q)` с регрессионным тестом на `examples_gold`.
- `codex-resource-offline-guard` — контроль 12 GB RAM / 16 GB VRAM / 6 часов и проверка `HF_HUB_OFFLINE=1`.
- `codex-git-submission-release` — чистые коммиты, финальная проверка сабмита через `submission.py` и подготовка к сдаче кода.
