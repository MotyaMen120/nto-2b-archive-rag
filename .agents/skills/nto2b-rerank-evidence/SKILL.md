# NTO 2B — Реранкинг и оптимизация Evidence (AP@5)

## Почему это критично
30% итоговой метрики — это `AP@5` по списку `evidence`. В `train`:
- Медиана золотых доказательств на вопрос = 3, 75-й перцентиль = 5, 90-й = 7, максимум = 20.
- Медиана уникальных каналов в золоте = 3 (до 12). Один и тот же факт пересказывают 3–6 пабликов в течение 0–2 дней.
- Плюс наличие хотя бы 1 правильного поста в `evidence` удваивает `a_q` с `0.5` до `1.0`!

## Пайплайн реранкинга (Stage 2)
1. **Вход**: топ-80..120 кандидатов от темпорального retrieval (`date <= D`).
2. **Cross-Encoder**: `BAAI/bge-reranker-v2-m3` (или `jina-reranker-v2-base-multilingual` / дообученный на `train` через `GroupKFold` кросс-энкодер + GBDT/neural meta-reranker).
   - Формат входа: `f"Дата вопроса: {asked_at}. Вопрос: {question}"` + `f"Дата поста: {post_date} ({channel_type}). {text}"`.
   - Если дообучаешь реранкер или GBDT-мета-ранкер на `train`, используй строго OOF по `train_groups.csv` и hard negatives из того же топа retrieval.
3. **Признаки для GBDT/Neural Meta-Reranker (дешёвые и мощные)**:
   - `bm25_score`, `dense_score`, `rrf_score`, `cross_encoder_logit`, `rank_in_each`.
   - `days_before_D = (D - post_date).days`, `log1p(days_before_D)`, флаг «пост в том же месяце, что и дата в вопросе».
   - `num_overlap` (совпадение чисел/годов между вопросом и постом), `entity_overlap`, `text_len`, `channel_type`.
   - `cluster_size_2d`: сколько ещё кандидатов из топ-50 имеют cosine > 0.85 в окне ±2 дня (сильный сигнал главной новости!).

## Сборка контекста для LLM (не только топ-K по скору!)
- Для `heavy` и `status` вопросов топ-10 по релевантности часто забивается 10 пересказами *одного* дня, вытесняя более ранний или более поздний пост истории.
- **Правило дедупликации контекста**: сгруппируй кандидатов в кластеры (cosine > 0.88 и `|Δdays| <= 2`). В контекст LLM бери **по 1–2 лучших (самых полных) поста из каждого уникального кластера/даты**, затем отсортируй выбранные 12–18 постов **строго хронологически по возрастанию `date`**.

## Постобработка `evidence` под AP@5 (Stage 4)
1. Если итоговый ответ `no_info` → `evidence = ""` (пустая строка; при верном `no_info` даётся `e_q = 1.0`).
2. Если ответ не `no_info`:
   - Попроси LLM явно вернуть `cited_post_ids` (1–3 опорных поста, из которых следует ответ).
   - **Валидируй `cited_post_ids`**: все ID должны быть из контекста и иметь `date <= D`.
   - **Кластерное расширение репостов (Repost Expansion)**:
     - Для каждого опорного поста `p` найди в кандидатах (`date <= D`) посты из **других каналов** в окне `|date - date(p)| <= 2 дня` с высокой близостью (`dense_cos(p, q) >= 0.84` или высокой близостью по тексту + совпадением ключевых чисел).
     - Ранжируй финальные 5 слотов: сначала самые уверенные опорные посты (если multi-hop — по 1 главному посту на каждый «хоп» в топ-2!), затем их ближайшие кросс-канальные репосты, затем оставшиеся топ-кандидаты реранкера.
   - **Для `skip`**: НИКОГДА не очищай `evidence`! Всегда клади топ-5 постов реранкера (`date <= D`), чтобы забрать `0.3 * AP@5`.
