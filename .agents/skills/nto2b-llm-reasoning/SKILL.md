# NTO 2B — LLM-рассуждения, Python-математика и строгие форматы

## Модель и бюджет на T4 16 GB
- В 4-bit (AWQ / GPTQ / bitsandbytes NF4) на 16 GB VRAM комфортно помещаются:
  - `Qwen/Qwen2.5-7B-Instruct` (~5.5 GB VRAM, быстро, 400 вопросов за ~15–25 мин);
  - `Qwen/Qwen2.5-14B-Instruct-AWQ` или `Qwen/Qwen3-8B` / `Qwen/Qwen3-14B-AWQ` (~9–10 GB VRAM, заметно сильнее на `heavy` и русских перифразах; 400 вопросов за ~40–90 мин).
- Ограничивай `max_model_len` (например, 6144–8192 токенов) и `max_new_tokens` (256–512), чтобы не упереться в OOM по KV-cache.

## Структурированный JSON-вывод (обязательно!)
LLM никогда не должна выдавать «сырой текст» без схемы. Требуй JSON:
```json
{
  "timeline": [{"date": "YYYY-MM-DD", "post_id": 12345, "fact": "..."}],
  "reasoning": "краткий вывод строго по постам <= D",
  "math_expr": {"op": "none|days_diff|full_months_diff|sub|div|pct_change|sum|count", "a": null, "b": null},
  "answer": "...",
  "evidence_ids": [12345, 12390],
  "confidence": 0.0
}
```

## Специализированные правила по `answer_format` и подтипам

### 1. `number` — Python-калькулятор вместо счёта в уме (36% всех `heavy`!)
- **Разница в днях** (`unit == "дней"`): LLM извлекает `date_start` и `date_end` (из текста поста или даты публикации поста, если спрашивают «от новости до новости»), а Python считает `(date_end - date_start).days`.
- **Полные месяцы** (`unit` содержит `месяц` / `полных месяцев`): Python считает:
  `months = (d2.year - d1.year) * 12 + (d2.month - d1.month) - (1 if d2.day < d1.day else 0)`.
- **Проценты, разности, суммы** (`на сколько % подорожало`, `сколько взрослых = всего - детей`, `цена семьи`): LLM извлекает операнды, Python считает формулу.
- **Нормализация единиц**: проверяй `unit` через `units.py`! Если `unit == "млн руб"`, а в посте «204,4 млрд руб», переводи в `204400`. Если `unit == "руб"`, а в посте «100 тыс. руб», переводи в `100000`. Формат: только число с точкой (без пробелов, `%`, `руб`).

### 2. `yesno` — Историческое состояние на прошлую дату (29% всех `heavy`!)
- Вопросы вида «Можно ли было 15 апреля...», «Шла ли стройка в июле...», «Горел ли вечный огонь в январе...»:
  - Построй интервал из таймлайна: `[дата закрытия/начала, дата открытия/окончания]`.
  - Проверь попадание целевой даты `T_target` в интервал (в Python или пошагово).
  - Помни: если посты $\le D$ лишь *обещали* действие на дату $\le D$, но подтверждения выполнения нет (пример `q1b757da7`, `q62003dd8`), правильный ответ — **`promised`**, а не `yes`!

### 3. `status` — Чёткая машина состояний
- `done`: есть пост $\le D$, **подтверждающий свершившийся факт** («открыли», «запустили», «прошли», «подписали», «потушили»).
- `cancelled`: есть пост $\le D$ об отмене/отказе («отменили», «отказались»).
- `postponed`: есть пост $\le D$ о переносе на новую дату/срок (и ещё не выполнено/не отменено).
- `promised`: в архиве $\le D$ есть обещание/план/контракт/анонс, но **нет подтверждения выполнения**, даже если плановая дата уже прошла!
- `no_info`: тема вообще не упоминается в постах $\le D$ (или нет информации по сути вопроса).

### 4. `date` — «Когда впервые написали» vs «На какую дату назначено» vs `promised`
- Если спрашивают «Когда впервые написали / сообщили...» → это **дата публикации самого раннего релевантного поста** в архиве $\le D$!
- Если спрашивают «С какого дня пустили / состоялся...» (факт в прошлом), а посты $\le D$ содержат только анонс на дату $> D$ (или без подтверждения факта) → ответ **`promised`** (пример `seed-D2-01`, `q84f1009a`).
- Строгий формат `YYYY-MM-DD`.

### 5. `choice` — Проверка ложных предпосылок (26% всех `choice`!)
- Передавай все 4 варианта `a, b, c, d` в промпт.
- Явно инструктируй LLM: «Сначала проверь предпосылку вопроса по постам. Если в вариантах есть «Предпосылка неверна / не проводился / не закрывали / проиграли вместо выиграли», проверь факты особенно тщательно».
- Ответ — строго одна строчная буква `a`, `b`, `c` или `d`.

## Усиление точности на сложных вопросах
- Для вопросов с признаками `heavy` (длинный вопрос, слова «сколько дней/месяцев/раз», «можно ли было», сравнение двух событий) запускай **Self-Consistency (2–3 прогона с разным порядком/температурой или verifier-проход)** и проверяй, что ответ подтверждён цитатой из поста $\le D$.
