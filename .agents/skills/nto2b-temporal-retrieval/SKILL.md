# NTO 2B — Темпоральный поиск и деобфускация запросов

## Главная особенность данных
Вопросы в кейсе намеренно используют описательные перифразы вместо прямых названий (например: «город химиков» → Дзержинск, «закрытый атомный город» → Саров, «райцентр пряников» → Городец, «зелёный зубастый хищник под мостом к ярмарке» → граффити крокодила на Канавинском мосту, «станция между Заречной и Пролетарской» → Двигатель Революции). Прямой BM25/E5 без раскрытия сущностей теряет Recall на `medium`/`heavy`.

## Архитектура поиска
1. **Жёсткая темпоральная маска**:
   - Отсортируй корпус по `date` один раз при индексации.
   - Для вопроса с датой `D` используй `upper_bound = np.searchsorted(sorted_dates, D, side='right')`. Поиск идёт только по срезу `[:upper_bound]`.
2. **Stage 0 — Query Expansion & Entity De-obfuscation (офлайн)**:
   - Сформируй компактный словарь нижегородских топонимов, объектов, команд («Торпедо», «Пари НН», «Химик», «Чайка») и аббревиатур — строго на основе корпуса и общих географических знаний (без внешних датасетов).
   - Используй локальную LLM (или rule+LLM гибрид) для генерации 2–3 поисковых запросов из исходного вопроса:
     - `q_direct`: раскрытые названия/топонимы/синонимы;
     - `q_event_start` / `q_event_end`: для вопросов с 2 событиями («сколько дней прошло от X до Y», «на сколько выросла цена между первым и вторым...», сравнения A vs B) — **два отдельных подзапроса**!
3. **Гибридный поиск (Lexical + Dense + RRF)**:
   - **Lexical**: `rank_bm25` / `bm25s` по лемматизированному тексту (`pymorphy3` или stemmer) + точные совпадения чисел/дат/маршрутов (`А-7`, `Э-4`, `№73`).
   - **Dense**: `intfloat/multilingual-e5-large` или `BAAI/bge-m3` / `deepvk/USER-bge-m3` (префикс `query:` / `passage:` для e5).
   - **Chunking**: 99% постов ≤ 232 слов (~1630 символов), но длинные посты (до 621 слова) режь на 2 чанка с перекрытием и агрегируй через `MaxP`.
   - **Fusion**: Reciprocal Rank Fusion (`1 / (60 + rank)`) по всем подзапросам и обоим индексам → топ-100..150 уникальных постов `<= D`.
4. **2-Hop Expansion для `heavy` (Multi-hop & Timeline)**:
   - Для вопросов типа «сколько дней прошло», «сколько раз переносили», «можно ли было <дата>...», `status`:
     - Возьми топ-5 постов первого прохода, извлеки из них ключевые сущности/названия (например, «Двигатель Революции», «Шуховская башня», «фуникулёр»).
     - Сделай второй запрос по всей истории `<= D`, чтобы вытащить **и самые ранние посты** (анонс/обещание/закрытие, разрыв до 626 дней!), **и самые поздние** (открытие/отмена/перенос).
     - Также добавляй темпоральное окно: если в вопросе упомянут конкретный месяц/дата (например, «в середине июня», «15 апреля 2025»), повышай вес постов в окне ±20 дней вокруг этой даты.

## Ограничения памяти (12 GB RAM)
- Эмбеддинги 142 226 × 1024 в `float16` занимают ~291 MB. Сохраняй их на диск (`np.save` / `memmap`) и загружай с `mmap_mode='r'`.
- Считай dot-product батчами по 20–30k постов, чтобы не создавать временные `float32` матрицы на гигабайты.
- После этапа retrieval выгружай эмбеддер из GPU и RAM (`del encoder; gc.collect(); torch.cuda.empty_cache()`).
